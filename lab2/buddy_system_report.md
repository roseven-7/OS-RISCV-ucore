# Lab2 Challenge：Buddy System 伙伴分配器

## 实现设计

在 kern/mm/buddy_system_pmm.c 中实现了一个基于物理页号的伙伴页分配器，并通过 buddy_system_pmm_manager 接入 pmm_manager 框架。每个阶数维护一条空闲链表，阶数 k 的块包含 2^k 个物理页；页号最低的 k 位为零，保证块按其大小对齐。Page.property 保存空闲块头的阶数，分配中的块头也暂存其阶数，以便现有 free_pages(base, n) 接口释放完整的向上取整块。

初始化时将任意长度的可用区间切成满足页号对齐约束的最大二次幂块。分配时寻找不小于请求量的最小阶数，从更大的块逐级拆分并把右半块加入对应空闲链表。释放时用 buddy_ppn = ppn XOR (1 << order) 找到物理伙伴；伙伴空闲且阶数相同时就移除并合并，直到无法继续合并。空闲页计数按实际伙伴块大小增减。

## Prompt 一：生成并接入 Buddy System

    你是熟悉 RISC-V ucore 的操作系统工程师。请先阅读当前仓库 lab2/kern/mm/pmm.h、memlayout.h、default_pmm.c、best_fit_pmm.c、pmm.c、libs/list.h 和已有检查代码，再在实际项目中实现 Buddy System 物理页分配器。

    接口与约束：
    1. 遵循 struct pmm_manager 的 init、init_memmap、alloc_pages、free_pages、nr_free_pages、check 六个接口；为新模块创建 buddy_system_pmm.c/.h，并定义 buddy_system_pmm_manager。
    2. 修改 pmm.c，使 init_pmm_manager() 选择 buddy_system_pmm_manager。不要改动 pmm_manager、Page、现有公共分配接口或 First-Fit/Best-Fit 测试。
    3. 每个空闲块包含 2 的阶数次方个连续物理页。用物理页号而不是描述符虚拟地址计算伙伴：伙伴页号为 ppn XOR (1 << order)。不能跨越 nbase、npage 管理范围或合并非空闲、不同阶数的块。
    4. 支持 init_memmap 输入长度不是 2 的幂且起点未按大块对齐的情况；将区间拆为多个合法的最大对齐伙伴块。不得把区间以外的页纳入管理。
    5. alloc_pages(n) 要求 n > 0，选择能容纳 n 页的最小阶数并向上取整；无足够连续伙伴块时返回 NULL。拆分时保留一半作为分配结果，将另一半登记为空闲块。nr_free_pages 返回实际空闲页数，按分配的伙伴块大小扣减。
    6. free_pages(base, n) 与现有 ucore 调用习惯兼容：base 是 alloc_pages 返回的块首描述符，n 是正数且不大于原分配大小；释放完整的向上取整伙伴块。校验页未保留、未在空闲链表中并清理引用计数，再循环合并空闲同阶伙伴。不要将描述符数组中其他页误当成块头。
    7. 在 check() 中设计可重复运行的自检，覆盖空闲链表和总页数一致、最小阶分配与拆分、非 2 的幂请求的取整、耗尽时失败、释放及伙伴合并。测试应隔离自己使用的页并在结束时恢复原分配器状态，不能破坏后续内核运行。
    8. 代码须符合仓库 GNU C/RISC-V 构建约定，不依赖动态内存、宿主库或未提供接口。保留清晰注释，加入文件后确认构建系统会自动收集 kern/mm 下的 C 文件，并运行项目提供的 Lab2 检查。

    请直接编辑仓库文件。完成后说明阶数和块对齐的表示方法、初始化/分配/释放流程、接口语义、边界处理、测试覆盖与实际构建结果；若发现框架约定与以上说明不一致，以仓库实际代码为准并指出差异。

## 测试覆盖及有效性

buddy_check() 在初始化检查时先校验每个空闲块的头标志、阶数、页号对齐，并累计各阶块大小与 buddy_nr_free 比较。它从真实分配器中预留 16 页，再暂存并隔离剩余阶数链表，在隔离区内执行以下检查：

- 申请 1 页后释放，检查拆分后的计数变化以及同阶伙伴逐级合并回 16 页块。
- 申请 3 页，检查向上取整到 4 页；释放后计数回到 16，且空闲链表重新满足无可合并同阶伙伴的性质。
- 将 16 页拆成两个 8 页块，申请耗尽时检查返回 NULL；只释放一个半块时，9 页申请仍失败；再释放另一半后检查合并和计数恢复。
- 对大于隔离区的请求检查失败，并在每组操作后校验空闲块对齐、阶数与空闲总量。

结束时移除隔离测试链表，把原有链表头和页数恢复，再将预留块正常释放回真实分配器并验证最终空闲页数等于测试前。这样能覆盖拆分和合并中的状态转换，也能发现越界合并、阶数错误、计数不一致以及测试污染真实空闲区的问题。
